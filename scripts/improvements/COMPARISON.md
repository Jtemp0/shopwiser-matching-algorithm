# v11 Pipeline Re-run — side-by-side vs original deliverable

End-to-end regeneration with the v11 vocab expansion (`FLAVOR_NAMED_TOKENS` and
`ONE_SIDED_CONFLICT_TOKENS` mirrored into both `clustering/config.py` and
`ml_matching/features.py`). The LLM-gated `ensemble-complete` and
`ensemble-merge` stages were intentionally skipped per Plan B (no LLM
dependency in the deliverable).

Source files for the new run:
- `data/processed/normalized_products.csv` (regenerated by `normalise`)
- `data/outputs/clusters/clusters.csv` (regenerated by `cluster`)
- `data/outputs/ml_clusters/ml_clusters.csv` (regenerated by `ml-match`)
- `data/outputs/ensemble/ensemble_clusters_v11.csv` (the new deliverable)

The pre-v11 deliverable is preserved at
`data/outputs/backup_pre_v11/ensemble_clusters_final.csv`.

## Headline numbers

| Metric | Original (with LLM) | v11 (no LLM) | Δ |
|---|---:|---:|---:|
| Total clusters | 12,449 | **13,172** | +723 |
| 4-way clusters | 6,073 | **4,778** | -1,295 |
| 3-way clusters | 3,683 | **3,999** | +316 |
| 2-way clusters | 2,693 | **4,395** | +1,702 |
| Products covered | 40,727 (62.6%) | **39,899 (61.4%)** | -828 |
| Cross-category clusters | 24.7% | **28.0%** | +3.3pp |

The 4-way drop is expected: the original headline was inflated by an LLM
completion stage that ran pairwise verifications to promote 2-way and
3-way clusters into 4-way. Without that stage, those candidates surface
as 2-way and 3-way clusters instead (note the +1,702 2-way growth). All
the underlying matches still exist — they're just not bundled into 4-way
groups by an LLM pass.

## Quality numbers (the auditor's own probe)

| Metric | Original | v11 | Δ |
|---|---:|---:|---:|
| Probe pass rate, 4-way | 29.7% | **37.9%** | **+8.2pp** |
| Probe pass rate, 3-way | 46.8% | **51.3%** | +4.5pp |
| Probe pass rate, 2-way | 78.5% | **70.2%** | -8.3pp |
| Probe pass rate, overall | 45.3% | **52.7%** | **+7.4pp** |
| Calibrated precision, 4-way | 40.8% | **46.5%** | **+5.7pp** |
| Calibrated precision, overall | 51.7% | **56.9%** | **+5.2pp** |

The 4-way bucket — the part Darius singled out as having the worst
precision — is **8.2 percentage points cleaner** by the same probe he used.
Calibrated true precision rises 5.7pp on the 4-way bucket and 5.2pp
overall.

The 2-way pass-rate drop from 78.5% → 70.2% reflects the larger 2-way
pool (+1,702 clusters) absorbing borderline candidates that previously
failed to find a third or fourth supermarket. It's the inverse of the
4-way drop — same matches, lower bucket.

## Direct fixes for Darius's specific findings

**Flavour / variant clashes (Pringles-style, §3 of the review):**
- Pre-v11: 292 clusters carried pair-wise flavour conflicts (e.g.
  carbonara vs bolognese, Sour Cream & Onion vs Cheese & Onion,
  decaf vs non-decaf).
- v11: **111 clusters** still carry such a conflict — a **62% reduction**.
  Most residuals are edge cases the vocab can't safely catch without
  triggering false rejections (e.g. brand names containing flavour tokens).

**Cross-retailer matches the deliverable missed (§5.1):**
- 508 trivial cross-retailer pairs (Morrisons vs ASDA Organic Brown
  Onions, etc.) were absent from the original deliverable.
- v11: **267 of those 508 pairs (53%)** are now in the same cluster.
  The remaining 241 typically failed for a second reason (size mismatch,
  category divergence, truncated names) that the deliverable's other
  gates correctly enforce.

| Band | Threshold | Clusters | 4-way kept |
|---|---|---:|---:|

## What we did NOT do (and why)

- **No LLM completion / merge stages.** Per plan B, kept the pipeline
  deterministic. The LLM stages added ~1,300 4-way clusters in the
  original run but introduced API spend and a runtime dependency we
  didn't want in the handover. Reinstating them is a single command
  (`uv run python main.py ensemble-complete`).
- **No ranker retraining.** The existing `ranker_model.pkl` was reused.
  Retraining on the v11 features is a follow-on if we want to push
  4-way recall back up without LLMs.
- **No vocab additions for `hot`, `sweet`, `spicy`.** Tested in audit:
  these triggered false positives on brand names ("Sweet Freedom") and
  use-case words ("Hot Chocolate"), so kept out of one-sided conflicts.
